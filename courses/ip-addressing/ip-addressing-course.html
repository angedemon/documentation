1. Binary numbers

1.1 Why binary?

Computers store everything as electrical states: on or off. Each state is a bit (binary digit) that is either 0 or 1. A group of 8 bits is a byte, also called an octet in networking. An IPv4 address is simply 32 bits; we write it as four decimal numbers only because humans read decimal more easily.

1.2 Positional number systems

In decimal (base 10) each position is worth ten times the position to its right:

Position103 = 1000102 = 100101 = 10100 = 1
4 7254725

4725 = 4×1000 + 7×100 + 2×10 + 5×1. Binary (base 2) works exactly the same way, but each position is worth twice the one to its right, and the only digits are 0 and 1.

1.3 The 8 bit values of an octet – learn them by heart

Bit position76543210
Power of 22726252423222120
Value1286432168421
  • The left-most bit is the most significant bit (MSB, worth 128); the right-most is the least significant bit (LSB, worth 1).
  • The largest value of an octet is 11111111 = 128+64+32+16+8+4+2+1 = 255; the smallest is 00000000 = 0. That is why each part of an IPv4 address is between 0 and 255: there are 28 = 256 possible values.
  • With n bits you can write 2n different values (from 0 to 2n − 1). This single rule is the heart of subnetting.

2. Hexadecimal

Hexadecimal (base 16) uses 16 digits: 0–9 then A=10, B=11, C=12, D=13, E=14, F=15. Its great advantage: one hex digit = exactly 4 bits (a nibble), so conversion with binary is immediate. Hex is used for MAC addresses and IPv6.

3. The binary AND operation

A device finds the network an address belongs to by computing address AND mask, bit by bit. The rule is: the result is 1 only if both bits are 1.

ABA AND B
000
010
100
111

Consequence: where the mask has 1s, the address bit is kept; where the mask has 0s, the bit becomes 0. ANDing with 255 keeps an octet unchanged, ANDing with 0 erases it.

Example: in which network is 192.168.10.77 with mask 255.255.255.192 (/26)?

Address  192.168.10.77    11000000.10101000.00001010.01001101
Mask     255.255.255.192  11111111.11111111.11111111.11000000
         ---------------------------------------------------- AND
Network  192.168.10.64    11000000.10101000.00001010.01000000

Only the last octet needs work: 77 = 01001101, AND 11000000 → 01000000 = 64. The network is 192.168.10.64.

Why it mattersWhen a host sends a packet, it ANDs its own address and the destination address with its mask. Same result → the destination is local, the packet is delivered directly (ARP). Different result → the destination is remote, the packet is sent to the default gateway.

4. Structure of an IPv4 address

An IPv4 address (Internet Protocol version 4, RFC 791) is a 32-bit number. It is written in dotted-decimal notation: four octets converted to decimal and separated by dots.

Decimal :      192   .    168   .     1    .    25
Binary  :  11000000 . 10101000 . 00000001 . 00011001
           |<------------------- 32 bits ------------------->|
  • Total address space: 232 = 4,294,967,296 addresses.
  • Each address has two parts: the network portion (identical for all devices of the same network, like a street name) and the host portion (unique for each device in it, like a house number).
  • The boundary between the two parts is given by the subnet mask (chapter 8).
192.168.1.25 /24     11000000.10101000.00000001.00011001
                     |<------ network: 24 bits ------>|<host: 8>|
Invalid addresses192.168.1.256 or 10.300.0.1 do not exist: an octet cannot exceed 255. Leading zeros (192.168.001.010) should be avoided – some software reads them as octal.

5. Address classes (classful addressing)

From 1981 to 1993 the address space was divided into fixed classes. The class is identified by the first bits of the first octet. Classes are obsolete for routing (replaced by CIDR in 1993), but they are still used in vocabulary, in exams, and to define default masks.

ClassFirst bitsFirst octet rangeDefault maskNetworksHosts per networkUse
A0xxxxxxx1 – 126255.0.0.0 (/8)12616,777,214Very large networks
B10xxxxxx128 – 191255.255.0.0 (/16)16,38465,534Medium networks
C110xxxxx192 – 223255.255.255.0 (/24)2,097,152254Small networks
D1110xxxx224 – 239—Multicast groupsMulticast
E1111xxxx240 – 255—ReservedExperimental

Network 0 and network 127 are excluded from class A (0 = “this network”, 127 = loopback), hence 126 usable class A networks. Class B: 214 networks (16 bits minus the 2 fixed bits); class C: 221 networks.

How to derive the ranges: class B starts with 10, so the first octet goes from 10000000 (128) to 10111111 (191). Class C starts with 110: 11000000 (192) to 11011111 (223).

Why classes were abandonedA company needing 2,000 addresses was too big for a class C (254) and received a class B (65,534): 63,000 addresses wasted. This waste, and the explosion of routing tables, led to CIDR (Classless Inter-Domain Routing, RFC 1519, 1993): the mask can now have any length. Today, “classful” only means the default mask.

A broadcast domain is the set of hosts reached by a broadcast; routers stop broadcasts. Creating subnets (and VLANs) splits a big broadcast domain into smaller ones – one of the main reasons for subnetting.

8. The subnet mask and CIDR notation

8.1 The subnet mask

The mask is a 32-bit value with 1s for the network part and 0s for the host part. The 1s are always contiguous and on the left.

255.255.255.0     11111111.11111111.11111111.00000000   → 24 network bits, 8 host bits
255.255.240.0     11111111.11111111.11110000.00000000   → 20 network bits, 12 host bits
255.255.255.252   11111111.11111111.11111111.11111100   → 30 network bits, 2 host bits

255.255.0.255 or 255.255.255.64 are invalid masks: the 1s are not contiguous (64 = 01000000 is not in the table of section 1.6).

8.2 CIDR (prefix) notation

Instead of writing the mask, we write a slash followed by the number of 1 bits: 192.168.1.25 /24 = mask 255.255.255.0. This number is called the prefix length.

Converting between the two

  • /20 → mask: 20 = 8 + 8 + 4 → 255 . 255 . (4 bits = 240) . 0 → 255.255.240.0.
  • 255.255.255.224 → prefix: 8 + 8 + 8 + (224 = 3 bits) = /27.
  • /13 → mask: 8 + 5 → 255 . (5 bits = 248) . 0 . 0 → 255.248.0.0.

8.3 The two fundamental formulas

With h host bits (h = 32 − prefix):
  • Number of addresses in the subnet = 2h
  • Number of usable hosts = 2h − 2 (minus the network address and the broadcast address)

When s bits are borrowed from the host part to create subnets:
  • Number of subnets = 2s

Examples: /24 → h = 8 → 256 addresses, 254 hosts. /26 → h = 6 → 64 addresses, 62 hosts. /30 → h = 2 → 4 addresses, 2 hosts (ideal for a link between two routers). /31 → 2 addresses, both usable on point-to-point links (RFC 3021). /32 → one single host (loopback interfaces, host routes).

The complete CIDR table is in chapter 17.

Network    192.168.10.64    11000000.10101000.00001010.01000000   host bits → 0

Worked example 2: 172.16.45.200/20

/20 = 255.255.240.0. The first two octets are entirely network, the fourth entirely host. Only the 3rd octet is shared (“interesting octet”): 4 network bits + 4 host bits.

Address  10101100.00010000.00101101.11001000
3rd octet: 45 = 00101101   → host bits to 0: 00100000 = 32  ;  host bits to 1: 00101111 = 47

Worked example 3: 10.45.123.77/13

2nd octet: 45 = 00101101   → network: 00101000 = 40   broadcast: 00101111 = 47

An address ending in .0 or .255 is not always invalidIn 192.168.0.0/23 (192.168.0.0 – 192.168.1.255), the address 192.168.0.255 and 192.168.1.0 are normal host addresses. Only the first and last addresses of the whole block are reserved. Always calculate; never judge by the last octet alone.

10. Subnetting (FLSM)

10.1 What and why

Subnetting means dividing one network into several smaller networks by borrowing bits from the host part and adding them to the network part. Reasons:

  • Reduce the size of broadcast domains (less broadcast traffic, better performance).
  • Security: separate departments, servers, guests, IoT, and filter traffic between them on the router/firewall.
  • Use the address space efficiently and match the physical/logical organisation (buildings, floors, VLANs).
  • Easier administration and troubleshooting.

In FLSM (Fixed Length Subnet Mask) all subnets have the same mask.

Before : 192.168.1.0 /24   11000000.10101000.00000001.00000000
After  : /26               11000000.10101000.00000001.00000000
                                     network (24)          subnet (2) host (6)

10.2 The method, step by step

  1. Determine how many bits to borrow: smallest s with 2s ≥ number of subnets needed – or smallest h with 2h − 2 ≥ hosts needed per subnet (then borrow the remaining bits).
  2. New prefix = old prefix + s. Write the new mask.
  3. Block size (increment) = 256 − value of the mask in the interesting octet (= 2number of host bits in that octet).
  4. List the subnets: start at the original network and add the block size each time.
  5. For each subnet: first host = network + 1, broadcast = next network − 1, last host = broadcast − 1.

10.3 Example A – by number of subnets: 192.168.1.0/24 into 4 subnets

  1. 4 subnets → 22 = 4 → borrow s = 2 bits.
  2. New prefix /24 + 2 = /26 → mask 255.255.255.192.
  3. Block size = 256 − 192 = 64.
  4. Subnets: .0, .64, .128, .192.
  5. Hosts per subnet: 26 − 2 = 62.

11. Fast subnetting: the “magic number” method

Once binary is understood, this mental method answers most questions in seconds, without writing 32 bits.

  1. Find the interesting octet: the octet where the mask is neither 255 nor 0.
  2. Magic number (block size) = 256 − mask value in that octet.
  3. Network: the largest multiple of the magic number that is ≤ the address value in the interesting octet. Octets to the right → 0.
  4. Broadcast: next network − 1 in the interesting octet; octets to the right → 255.

Example: 200.15.7.99/29

  • /29 = 255.255.255.248 → interesting octet = 4th, magic number = 256 − 248 = 8.
  • Multiples of 8: … 88, 96, 104 … → 99 falls in the block 96–103.
  • Network 200.15.7.96, broadcast 200.15.7.103, hosts .97 – .102 (6 hosts).

Example: 172.16.45.200/20 (again)

  • 255.255.240.0 → 3rd octet, magic number 16 → multiples 0, 16, 32, 48 → 45 is in 32–47.
  • Network 172.16.32.0, broadcast 172.16.47.255. Same as the binary method, much faster.

Are two hosts in the same subnet?

192.168.1.62/26 and 192.168.1.65/26: block 64 → .62 is in 0–63, .65 is in 64–127 → different subnets; they need a router to communicate even though their addresses are “close”.

Quick reference: prefix ↔ magic number
4th octet/25: 128/26: 64/27: 32/28: 16/29: 8/30: 4/31: 2/32: 1
3rd octet/17: 128/18: 64/19: 32/20: 16/21: 8/22: 4/23: 2/24: 1
2nd octet/9: 128/10: 64/11: 32/12: 16/13: 8/14: 4/15: 2/16: 1

12. VLSM – Variable Length Subnet Masking

With FLSM, all subnets are the size of the largest need: a link between two routers (2 hosts) would consume a /26 of 62 addresses – 60 wasted. VLSM allows a different mask for each subnet, sized to its real need. It requires classless routing protocols (OSPF, EIGRP, RIPv2, BGP, static routes) – all modern ones.

12.1 The method

  1. List all needs (hosts per network, plus point-to-point links).
  2. Sort them from largest to smallest – essential to keep blocks aligned and avoid overlaps.
  3. For each need, choose the smallest prefix with 2h − 2 ≥ hosts (remember to count the router interface/gateway as a host).
  4. Allocate the first subnet at the start of the block; each next subnet starts right after the previous broadcast address.
  5. Check that a subnet always starts on a multiple of its own block size.

Detail of choices: 100 → 27 − 2 = 126 → /25; 50 → 62 → /26; 25 → 30 → /27; 10 → 14 → /28; 2 → 2 → /30. Remaining free: 192.168.10.252/30 for future use. In FLSM with /25 masks we could have created only 2 networks; VLSM fits 7 networks in the same /24.

Overlap: the classic VLSM mistakeIf you allocate small subnets first (e.g. 192.168.10.0/30), then try to place a /25 at 192.168.10.0, the two overlap. A /25 can only start at .0 or .128, a /26 at .0/.64/.128/.192, etc. Sorting from largest to smallest guarantees correct alignment.

13. Supernetting and route summarization

13.1 Principle

Supernetting is the opposite of subnetting: several contiguous networks are combined into one larger network by shortening the prefix (moving bits from the network part back to the host part). Used for:

  • Route summarization (aggregation): a router advertises one route instead of many → smaller routing tables, less CPU and memory, faster convergence, and instabilities of a small network are hidden from the rest.
  • CIDR allocation: an ISP gives a customer who needs 1,000 addresses a /22 (1,024 addresses) instead of four separate class C networks.

13.2 Method: find the common bits

  1. Write the networks in binary (only the octet that differs is needed).
  2. Count the left-most bits common to all of them → that is the summary prefix.
  3. Summary address = common bits followed by zeros.
  4. Verify that the summary does not include networks that are not yours.

Example 1 – 192.168.0.0/24 to 192.168.3.0/24

192.168.0.0   11000000.10101000.00000000.00000000
192.168.1.0   11000000.10101000.00000001.00000000
192.168.2.0   11000000.10101000.00000010.00000000
192.168.3.0   11000000.10101000.00000011.00000000
              |<-------- 22 common bits -------->|

Summary: 192.168.0.0/22 (mask 255.255.252.0), covering exactly 192.168.0.0 – 192.168.3.255.

Example 2 – 172.16.12.0/24 to 172.16.15.0/24

12 = 00001100    13 = 00001101    14 = 00001110    15 = 00001111

16 + 6 = 22 common bits → 172.16.12.0/22.

Example 3 – 10.1.64.0/24 to 10.1.127.0/24 (64 networks)

64 = 01000000, 127 = 01111111 → 16 + 2 = 18 common bits → 10.1.64.0/18. One route replaces 64.

Example 4 – two /25 into a /24

198.51.100.0/25 + 198.51.100.128/25 → 198.51.100.0/24.

13.3 Rules and traps

  • The number of networks summarized exactly is always a power of two (2, 4, 8, 16…).
  • The first network must be a multiple of that number in the interesting octet (4 networks → start at 0, 4, 8, 12…; 8 networks → 0, 8, 16…).
Non-aligned networks: 192.168.1.0/24 to 192.168.4.0/24 1 = 00000001, 2 = 00000010, 3 = 00000011, 4 = 00000100: only 21 bits in common → 192.168.0.0/21, which also covers 192.168.0.0, .5.0, .6.0 and .7.0 – networks that may belong to someone else (over-summarization, causing traffic to be black-holed). The exact minimum summary is three routes: 192.168.1.0/24, 192.168.2.0/23, 192.168.4.0/24.

Quick method without binary

Count the networks (N), round up to a power of two 2k, the summary prefix is old prefix − k; check that the first network is a multiple of 2k. Example: 8 networks 10.0.8.0/24 … 10.0.15.0/24 → 23 → /24 − 3 = /21; 8 is a multiple of 8 ✓ → 10.0.8.0/21.

15. NAT and PAT

NAT (Network Address Translation, RFC 3022) lets hosts with private addresses reach the Internet: the router replaces the private source address with a public one and remembers the mapping to translate replies back.

Inside 192.168.1.25:51000  ─┐                         ┌─→ 93.184.215.14:443
Inside 192.168.1.30:51000  ─┼─ Router PAT 203.0.113.7 ┤   (seen as 203.0.113.7:40001

Terminology (Cisco): inside local = private address of the host, inside global = public address representing it, outside global = address of the remote server. Drawbacks of NAT: breaks end-to-end connectivity, complicates incoming connections, VoIP and some VPN protocols – IPv6 removes the need for it.

To know your public address: curl ifconfig.me (Linux) or curl.exe ifconfig.me (Windows) – compare it with ipconfig/ip a which shows the private address.

16. IPv6 addressing

16.1 Format

IPv6 (RFC 8200) uses 128-bit addresses: 2128 ≈ 3.4 × 1038 addresses. They are written as 8 groups of 4 hexadecimal digits (16 bits each, called hextets) separated by colons.

2001:0db8:0000:0000:0000:ff00:0042:8329

Abbreviation rules (RFC 5952)

  1. Leading zeros of each group may be removed: 0db8 → db8, 0042 → 42, 0000 → 0.
  2. One sequence of consecutive all-zero groups may be replaced by :: – only once per address (otherwise the length would be ambiguous). Replace the longest run; if two runs are equal, the left-most one.
  3. Use lowercase letters.
2001:0db8:0000:0000:0000:ff00:0042:8329  →  2001:db8::ff00:42:8329
2001:0db8:0000:0000:0001:0000:0000:0001  →  2001:db8::1:0:0:1        (left-most run compressed)
0000:0000:0000:0000:0000:0000:0000:0001  →  ::1                      (loopback)
fe80::1   expanded  →  fe80:0000:0000:0000:0000:0000:0000:0001

To expand: count the groups present, the :: stands for as many 0000 groups as needed to reach 8.

16.2 Structure of a global unicast address

|<--- 48 bits --->|<- 16 bits ->|<---------- 64 bits ---------->|
  Global routing      Subnet ID          Interface ID
  prefix (from ISP)   (your subnets)     (identifies the host)
  2001:db8:abcd    :    0012       :  3e52:82ff:fe1a:4f9e

A LAN in IPv6 is always a /64. A site usually receives a /48 (or /56 for homes), leaving 16 bits (or 8) for subnets: 65,536 subnets of 264 hosts each. Subnetting IPv6 is therefore simple: you just increment the subnet ID in hex: 2001:db8:abcd:0000::/64, 2001:db8:abcd:0001::/64 … 2001:db8:abcd:ffff::/64.

There is no broadcast in IPv6: it is replaced by multicast. Anycast addresses are normal unicast addresses assigned to several devices.

16.4 How hosts get an IPv6 address

  • SLAAC (Stateless Address Autoconfiguration): the router sends a Router Advertisement with the /64 prefix; the host builds its interface ID itself (random, for privacy – RFC 8981 – or with EUI-64).
  • DHCPv6: stateful (server assigns addresses) or stateless (only DNS info, address by SLAAC).
  • Static configuration.

EUI-64 example: MAC 3c:52:82:1a:4f:9e

  1. Split the MAC in two halves: 3c5282 | 1a4f9e.
  2. Insert fffe in the middle: 3c5282fffe1a4f9e.
  3. Invert the 7th bit (U/L bit) of the first byte: 3c = 0011 1100 → 0011 1110 = 3e.
  4. Interface ID: 3e52:82ff:fe1a:4f9e → link-local fe80::3e52:82ff:fe1a:4f9e.

17.3 Common mistakes checklist

  • Forgetting the −2 (network and broadcast) when counting hosts.
  • Forgetting that the router (gateway) also needs an address in each subnet.
  • Thinking 172.32.x.x is private (only 172.16–172.31 is).
  • Judging an address invalid because it ends in .0 or .255 without computing the subnet.
  • Using a non-contiguous mask (255.255.255.64).
  • Not sorting needs from largest to smallest in VLSM → overlapping subnets.
  • Summarizing a range that is not a power of two or not aligned → over-summarization.
  • Using :: twice in an IPv6 address.
